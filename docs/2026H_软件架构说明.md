# 2026H 项目软件架构说明

> 适用仓库：`https://github.com/YWJimmy/2026H`  
> 适用主控：STM32F407ZGT6  
> 开发方式：STM32CubeMX + HAL + C语言  
> 本文用于队员协作，也用于让其他 AI 快速理解项目结构和代码边界。

---

## 1. 我们为什么需要分层

本项目同时包含：

- 8 路 ADC 巡线
- 双电机和双编码器
- 舵机控制
- MPU6050
- OLED
- 蓝牙通信
- 视觉模块通信
- 多个比赛任务

如果所有代码都写在 `main.c` 中，后续会出现：

- 找不到某段代码属于哪个模块
- 修改一个功能时影响其他功能
- 多人同时开发容易冲突
- AI 无法判断代码应该放在哪里
- 复杂任务难以组合和复用

因此，本项目采用一个简单的四层结构：

```text
App 应用层
    ↓
Action 动作层
    ↓
Module 模块层
    ↓
BSP 板级驱动层
    ↓
CubeMX / HAL / STM32硬件
```

---

## 2. 四层分别负责什么

### 2.1 BSP：直接控制硬件

BSP 是 Board Support Package，中文可理解为“板级支持代码”。

它负责把 CubeMX 和 HAL 的底层接口，封装成项目能直接使用的硬件接口。

例如：

```c
__HAL_TIM_SET_COMPARE(&htim9, TIM_CHANNEL_1, pwm);
HAL_GPIO_WritePin(MOTOR_L_IN1_GPIO_Port, MOTOR_L_IN1_Pin, GPIO_PIN_SET);
```

这些代码不应该到处出现，而应该集中放在 BSP 中。

建议目录：

```text
User/bsp/
├─ bsp_motor.c
├─ bsp_motor.h
├─ bsp_encoder.c
├─ bsp_encoder.h
├─ bsp_servo.c
├─ bsp_servo.h
├─ bsp_line_adc.c
├─ bsp_line_adc.h
├─ bsp_oled.c
├─ bsp_oled.h
├─ bsp_mpu6050.c
├─ bsp_mpu6050.h
├─ bsp_vision_uart.c
└─ bsp_vision_uart.h
```

BSP 示例接口：

```c
void BSP_Motor_SetLeftPwm(uint16_t pwm);
void BSP_Motor_SetRightPwm(uint16_t pwm);
void BSP_Motor_Enable(bool enable);

int16_t BSP_Encoder_GetLeftDelta(void);
int16_t BSP_Encoder_GetRightDelta(void);

void BSP_Servo_SetPulseUs(uint16_t pulse_us);
```

### BSP 的原则

- 可以调用 HAL
- 可以使用 `htimx`、`huartx`、`hi2cx`
- 可以操作 GPIO
- 可以读写定时器计数器
- 不负责 PID
- 不负责比赛任务
- 不负责“前进一圈”这种动作

---

### 2.2 Module：实现一个完整功能模块

Module 在 BSP 之上，实现一个完整功能。

建议目录：

```text
User/module/
├─ chassis.c
├─ chassis.h
├─ line_follow.c
├─ line_follow.h
├─ ball_control.c
├─ ball_control.h
├─ vision.c
├─ vision.h
├─ display.c
└─ display.h
```

主要模块：

| 模块 | 作用 |
|---|---|
| `chassis` | 双电机、双编码器、速度闭环、底盘运动 |
| `line_follow` | 读取 8 路 ADC，计算巡线误差并控制底盘 |
| `ball_control` | 根据视觉位置控制舵机，使钢球到目标位置 |
| `vision` | 接收并解析视觉模块发送的数据 |
| `display` | OLED 页面和比赛时间显示 |

例如，底盘模块可以提供：

```c
void Chassis_Init(void);
void Chassis_SetSpeed(float left_speed, float right_speed);
void Chassis_SetForwardSpeed(float speed);
void Chassis_Stop(void);
void Chassis_Update(void);
float Chassis_GetDistance(void);
```

上层只调用：

```c
Chassis_SetForwardSpeed(0.6f);
```

上层不需要知道：

- 左电机使用 TIM9_CH1
- 右电机使用 TIM9_CH2
- 左编码器使用 TIM3
- 右编码器使用 TIM4
- 电机方向脚具体是哪几个 GPIO

这些硬件细节由 BSP 隔离。

---

### 2.3 Action：实现一个动作

Action 表示一个可以启动、持续更新、完成或失败的动作。

分为两类：

#### 单模块动作

例如：

- 前进 500 mm
- 停车
- 钢球移动到 `+5 cm`
- 钢球稳定在 `0 cm`
- 循线行驶一段距离

建议文件：

```text
User/action/
├─ action_move.c
├─ action_move.h
├─ action_ball_move.c
├─ action_ball_move.h
├─ action_ball_hold.c
├─ action_ball_hold.h
├─ action_line_follow.c
└─ action_line_follow.h
```

#### 复杂动作

复杂动作可以同时调用多个模块。

例如：

- 小车循线，同时钢球稳定在中心
- 小车跑一圈，在 A 点停车
- 小车从 A 到 B，同时滚球控制保持运行

建议文件：

```text
User/action/
├─ action_task2.c
├─ action_task2.h
├─ action_task3.c
├─ action_task3.h
├─ action_task4.c
├─ action_task4.h
├─ action_task5.c
├─ action_task5.h
├─ action_task6.c
└─ action_task6.h
```

所有 Action 尽量统一使用以下接口：

```c
void ActionXxx_Start(void);
void ActionXxx_Update(void);
void ActionXxx_Stop(void);
bool ActionXxx_IsFinished(void);
bool ActionXxx_HasFailed(void);
```

例如：

```c
ActionMove_Start(500.0f, 300.0f, 5000U);

while (1)
{
    ActionMove_Update();

    if (ActionMove_IsFinished())
    {
        break;
    }
}
```

上面的 `while` 只用于说明调用关系。正式程序中不应使用这种阻塞等待，而应由 `App_Update()` 周期调用。

### Action 的原则

- 不直接调用 HAL
- 不直接修改定时器和 GPIO
- 只调用 Module 的公开接口
- 必须支持完成状态
- 建议支持超时和失败状态
- 不使用 `HAL_Delay()` 等待动作完成
- 不使用长时间阻塞的 `while`

---

### 2.4 App：应用层和任务入口

App 是整个项目的最高层。

它负责：

- 初始化各模块
- 等待启动按键
- 选择比赛任务
- 启动对应 Action
- 周期更新当前任务
- 处理完成、超时和故障
- 控制 OLED 显示状态

建议目录：

```text
User/app/
├─ app.c
└─ app.h
```

建议接口：

```c
void App_Init(void);
void App_Update(void);
```

`main.c` 应尽量保持简单：

```c
int main(void)
{
    HAL_Init();
    SystemClock_Config();

    MX_GPIO_Init();
    MX_DMA_Init();
    MX_ADC1_Init();

    MX_I2C1_Init();
    MX_I2C2_Init();

    MX_USART1_UART_Init();
    MX_USART2_UART_Init();
    MX_USART6_UART_Init();

    MX_TIM1_Init();
    MX_TIM3_Init();
    MX_TIM4_Init();
    MX_TIM9_Init();

    App_Init();

    while (1)
    {
        App_Update();
    }
}
```

`main.c` 中不应直接实现：

- 巡线算法
- 编码器速度计算
- 电机 PID
- 钢球 PID
- 视觉协议解析
- 比赛任务状态机

## 4. 一次调用是怎样经过各层的

以“左电机前进”为例：

```text
App
  ↓
ActionMove
  ↓
Chassis
  ↓
BSP_Motor
  ↓
HAL_TIM / HAL_GPIO
  ↓
TIM9、GPIO、TB6612、电机
```

以“任务 5：循线一圈，同时稳定钢球”为例：

```text
App
  ↓
ActionTask5
  ├─ LineFollow_Update()
  │      ↓
  │   Chassis_SetSpeed()
  │      ↓
  │   BSP_Motor
  │
  ├─ BallControl_Update()
  │      ↓
  │   BSP_Servo
  │
  └─ Vision_Update()
         ↓
      BSP_VisionUart
```

## 6. 文件应该放在哪一层

遇到新代码时，可以按下面的问题判断。

### 问题 1：代码是否直接操作 HAL、GPIO、TIM、UART、I2C 或 ADC？

是：

```text
放入 User/bsp/
```

例如：

```c
HAL_GPIO_WritePin(...);
HAL_UART_Receive_DMA(...);
__HAL_TIM_SET_COMPARE(...);
```

---

### 问题 2：代码是否实现一个完整功能？

是：

```text
放入 User/module/
```

例如：

- 编码器测速
- 电机速度 PID
- 8 路巡线误差计算
- 视觉数据解析
- 钢球位置闭环

---

### 问题 3：代码是否表示“做一次什么事情”？

是：

```text
放入 User/action/
```

例如：

- 前进 500 mm
- 循线一圈
- 钢球移动到 +5 cm
- 一边循线一边稳定钢球

---

### 问题 4：代码是否负责选择任务和管理整个程序？

是：

```text
放入 User/app/
```

## 7. 开发时必须遵守的规则

### 规则 1：不要修改 ST 官方 Drivers

```text
Drivers/
├─ CMSIS/
└─ STM32F4xx_HAL_Driver/
```

这里主要是 ST 官方代码，通常不要手动修改。

---

### 规则 2：CubeMX 生成文件只做初始化

`Core/Src` 中的：

- `gpio.c`
- `adc.c`
- `tim.c`
- `i2c.c`
- `usart.c`

主要由 CubeMX 维护。

业务代码不要大量写进这些文件。

---

### 规则 3：main.c 保持简单

`main.c` 只负责：

```text
HAL初始化
→ CubeMX外设初始化
→ App_Init()
→ 循环调用 App_Update()
```

---

### 规则 4：上层不要直接使用硬件句柄

这些内容只应出现在 BSP 或 CubeMX 文件中：

```c
&htim1
&htim3
&htim4
&htim9
&huart2
&huart6
&hi2c1
&hi2c2
GPIOA
GPIOB
HAL_GPIO_WritePin()
```

Module、Action、App 不应直接依赖具体硬件引脚。

---

### 规则 5：动作必须非阻塞

错误写法：

```c
while (distance < target)
{
    /* 一直等待 */
}
```

错误写法：

```c
HAL_Delay(5000);
```

推荐写法：

```c
void ActionMove_Update(void)
{
    if (Chassis_GetDistance() >= target_distance)
    {
        Chassis_Stop();
        action_finished = true;
        return;
    }

    Chassis_SetForwardSpeed(target_speed);
}
```

`App_Update()` 会反复调用它，因此其他模块也能同时运行。

---

### 规则 6：一个文件只负责一类事情

例如：

```text
bsp_motor.c
```

只负责电机 PWM、方向和 STBY。

不要在里面实现：

- 巡线 PID
- 跑一圈逻辑
- 钢球控制
- OLED 页面

---

## 8. 给队员的简单理解方式

可以把整个系统理解成：

```text
BSP：硬件怎么动
Module：一个功能怎么工作
Action：这一次要做什么
App：现在执行哪个任务
```

例如：

```text
BSP_Motor：
设置电机 PWM

Chassis：
控制左右轮速度

ActionMove：
让小车前进 500 mm

App：
按键后开始任务 2
```

## 9. 给其他 AI 的项目说明

以下内容可直接提供给其他 AI：

```text
项目名称：2026H
远程仓库：https://github.com/YWJimmy/2026H
主控：STM32F407ZGT6
开发方式：STM32CubeMX + HAL + C语言

软件采用四层架构：

1. User/bsp
   直接调用 HAL，封装具体硬件。
   只有这一层可以直接使用 TIM、GPIO、UART、I2C、ADC 和 HAL 句柄。

2. User/module
   实现完整功能模块，例如 chassis、line_follow、ball_control、vision。
   不直接访问 HAL。

3. User/action
   实现单个动作或复杂动作。
   单个动作例如前进指定距离、钢球移动到指定位置。
   复杂动作可以同时调用循线、底盘、滚球和视觉模块。
   Action 必须采用 Start/Update/Stop/IsFinished 形式，禁止阻塞等待。

4. User/app
   负责按键启动、任务选择、任务状态、完成与故障处理。
   main.c 只初始化外设、调用 App_Init，并在主循环调用 App_Update。

调用关系：
App → Action → Module → BSP → HAL

项目当前主要硬件映射：
- TIM9_CH1 / PE5：左电机 PWM
- TIM9_CH2 / PE6：右电机 PWM
- TIM3_CH1/CH2 / PC6、PC7：左编码器
- TIM4_CH1/CH2 / PD12、PD13：右编码器
- TIM1_CH1 / PA8：舵机 PWM
- ADC1_IN8～IN15：8 路巡线 ADC
- I2C1：OLED
- I2C2：MPU6050
- USART2：蓝牙
- USART6：视觉模块

修改代码前必须先查看仓库最新内容和 2026H.ioc。
不要修改 Drivers 中的 ST 官方代码。
不要把业务逻辑写进 main.c。
每次修改都要说明新增、修改和删除的文件，并给出 Git commit message。
```

## 10. 当前阶段建议先实现的文件

不要一开始创建很多空文件。

第一阶段只需要：

```text
User/
├─ bsp/
│  ├─ bsp_motor.c
│  ├─ bsp_motor.h
│  ├─ bsp_encoder.c
│  ├─ bsp_encoder.h
│  ├─ bsp_servo.c
│  └─ bsp_servo.h
│
├─ module/
│  ├─ chassis.c
│  └─ chassis.h
│
├─ action/
│  ├─ action_move.c
│  └─ action_move.h
│
└─ app/
   ├─ app.c
   └─ app.h
```

先完成：

```text
电机 PWM
→ 电机方向
→ 编码器读取
→ 轮速计算
→ 速度闭环
→ 前进指定距离
```

确认底盘基础稳定后，再加入巡线、视觉和滚球模块。

## 11. 一句话总结

```text
底层硬件放 BSP，
完整功能放 Module，
具体动作放 Action，
比赛任务由 App 统一调用。
```
