# K230D 绿色管道小钢球识别

本目录提供正点原子 K230D BOX 上可直接部署的小钢球单类别 YOLOv8n 模型与
CanMV MicroPython 脚本。当前最终使用场景为：画面中只有一个小钢球，小钢球在
绿色管道内运动。

## 当前推荐部署

```text
开发板：正点原子 K230D BOX
摄像头：GC2093
固件：CanMV_K230D_ATK_DNK230D_micropython_v1.8-0-gc2d1f5c_nncase_v2.11.0
类别：steel_ball（单类别，class_id=0）
模型：YOLOv8n detect
量化：W8A8
模型输入：320x320
传感器视场：1280x960
AI 图像通道：320x240 RGB888P
候选阈值：0.11
首次锁定阈值：0.13
跟踪阈值：0.11
NMS IoU 阈值：0.45
```

| 文件 | 用途 |
|---|---|
| `steel_ball_yolov8n_320_v2_full_nncase211_w8a8.kmodel` | 当前推荐的绿色管道全图 W8A8 KPU 模型 |
| `steel_ball_yolov8_v2_full_w8a8_stable.py` | 摄像头采集、推理、单目标选择、显示和 `SB` 输出入口 |
| `steel_ball_temporal_tracker.py` | 一帧短时跟踪、速度滤波和延迟补偿 |

## 与 STM32F407 串口连接

K230D BOX 使用 PH2.0 接口1，对应 K230D `UART1`：

```text
K230D PH2.0接口1 UART1_TXD / IO40 → STM32 PG9  / USART6_RX
K230D PH2.0接口1 UART1_RXD / IO41 ← STM32 PG14 / USART6_TX
K230D GND                            ↔ STM32 GND
```

两端统一使用 `115200, 8N1`，无硬件流控。TX/RX 必须交叉连接并共地。
当前 K230D 只主动发送检测结果，保留 RX 接线用于后续命令或握手扩展。

模型大小：`3,365,584` 字节；SHA-256：

```text
25adc9a388fbf3324335f303fbdcd23bc47c3d02e40e352c9822124337c0262d
```

目录中原有的 W8A16 模型、`steel_ball_yolov8_v18.py` 和诊断脚本作为历史版本保留，
新的绿色管道场景应使用上表中的三个文件。

## 针对绿色管道重新训练

旧模型主要面向白纸等简单背景。确定小钢球最终只在绿色管道内运动后，重新补充了
绿色管道静态样本、快速运动样本和无球/易混淆负样本，按连续拍摄场景重新分组数据集，
重新训练全图模型，并重新执行 nncase 2.11.0 量化与离线验证。

当前部署选择 W8A8。候选阈值扫描中，`0.11`、`0.12` 和 `0.13` 均保持测试正样本
`107/107` 检出且负样本 `0/17` 误检；`0.10` 开始出现 `1/17` 负样本误检，因此运行
入口使用 `0.11` 作为跟踪候选阈值，并使用更高的 `0.13` 完成首次锁定。

## 当前识别与跟踪策略

1. GC2093 使用 `1280x960` 传感器视场，独立 `320x240 RGB888P` AI 通道经纵向
   letterbox 后送入 `320x320` YOLOv8n KModel。
2. 移除 letterbox 纵向偏移，将检测框映射回 `1280x960` 坐标。
3. 全图模型保持原有输入和预处理不变。相机今后固定在 `15.bmp` 对应位置，后处理
   只接受中心位于绿色管道斜带 ROI 内的候选框：`x=100～1200`，中心线为
   `cy=437-0.034*cx`，上下容差 `±70 px`。该范围覆盖实测球心行程
   `cx=153～1160`，并在两端保留识别抖动余量；管道外候选不会参与置信度比较或
   运动匹配。K230D 屏幕会始终用黄色四边线显示该 ROI，检测框继续使用绿色；即使
   当前没有识别到小球，ROI 边界也不会消失。
4. 未锁定目标时，从合法候选框中选择置信度最高的一个。
5. 已锁定目标时，先剔除尺寸、管道范围和运动轨迹不合理的候选，再选择最接近预测
   位置的一个；距离相同时才比较置信度。画面中始终只输出一个目标，可降低杂物抢框。
6. 检测漏掉一帧时使用短时预测，第二帧仍未恢复则释放目标。预测帧保持绿色显示，
   文本显示 `predicted`，串口使用 `score_milli=0` 标识。
7. 只对速度做低通滤波，不平滑原始检测位置。当前速度占 `35%`，历史速度占 `65%`。
8. 延迟补偿采用速度滞回：速度达到 `5 px/帧` 时开启，降到 `2 px/帧` 时关闭；
   反向当帧清空滤波速度且不补偿。
9. 串口坐标补偿 `25 ms`，显示框补偿 `30 ms`，两者都严格限制为最多一帧。

实机日志中，KPU 推理中位数约 `24.55 ms`，普通循环约 `29.5 ms`。速度补偿用于消除
快速运动时约一个球身的视觉和坐标延迟；最终参数仍应以正式机构上的连续运行结果为准。

## 部署方法

将以下三个文件复制到 SD 卡根目录：

```text
/sdcard/steel_ball_yolov8n_320_v2_full_nncase211_w8a8.kmodel
/sdcard/steel_ball_temporal_tracker.py
/sdcard/steel_ball_yolov8_v2_full_w8a8_stable.py
```

在 CanMV IDE 中运行：

```text
steel_ball_yolov8_v2_full_w8a8_stable.py
```

需要脱机启动时，在实机连续运行验收通过后，将运行入口复制为 SD 卡根目录下的
`main.py`。模型文件名必须与脚本中的 `KMODEL_PATH` 完全一致。

## 输出协议

稳定部署脚本通过 PH2.0 接口1的 UART1 发送 ASCII 文本帧，每帧以 `\r\n`
结束；同样内容同时保留在 CanMV IDE 串行终端中，便于调试。

检测到小钢球：

```text
SB,1,x1,y1,x2,y2,cx,cy,score_milli
```

未检测到小钢球：

```text
SB,0,0,0,0,0,0,0,0
```

| 字段 | 含义 |
|---|---|
| `SB` | 小钢球协议帧头 |
| `1/0` | `1` 表示当前有目标，`0` 表示无目标 |
| `x1,y1,x2,y2` | `1280x960` 坐标系中的补偿后检测框 |
| `cx,cy` | 补偿后检测框中心，计算式为 `(x1+x2)//2, (y1+y2)//2` |
| `score_milli` | 观测置信度乘以 1000；短时预测帧为 `0` |

显示框使用 `30 ms` 补偿，串口坐标使用 `25 ms` 补偿，因此运动时两者可能相差少量
像素；静止时两者一致。`cx,cy` 是视觉检测框中心，不是三维空间坐标。

STM32 在 `SB` 帧通过格式、范围和中心一致性校验后，按固定相机下的五点实测标定
进行分段线性插值，并把结果写入 `VisionBallFrame_t.physical_x_mm`：

| `cx` | 153 | 447 | 653 | 869 | 1160 |
|---:|---:|---:|---:|---:|---:|
| 实际横坐标 | -120 mm | -50 mm | 0 mm | +50 mm | +120 mm |

图像右侧为物理正方向。标定范围外的输入饱和到 `-120 mm` 或 `+120 mm`；无目标帧
保持 `found=false` 且 `physical_x_mm=0`。串口原始 `SB` 协议不增加字段，避免破坏
K230D 与 STM32 已有通信兼容性；STM32 调试输出通过 `X_MM=` 显示换算结果。

## 实机验收建议

1. 静止小球：框应稳定，速度补偿保持关闭。
2. 慢速运动：框应少量前移，不应在球前后反复跳动。
3. 快速运动：显示框不再落后约一个球身，串口坐标连续。
4. 急停和反向：反向当帧不补偿，框不应明显冲过头。
5. 无球和杂物：不应被远处高分杂物持续抢框。
6. 连续运行：检查 `[STEEL-PERF]` 中推理时间和 `mem_free` 是否稳定。

如仍出现固定杂物误检，应继续把该杂物的无球画面作为负样本加入原始数据，再按拍摄
场景重新分组、训练和量化，不要只通过继续降低阈值解决。
